# Books

EPUB and PDF, with the same reader / writer / wizard treatment audiobooks have.
The design is in `superpowers/specs/2026-09-01-book-formats-design.md`.

## EPUB

An EPUB is a zip. Foundation has no zip API and `DECISIONS.md` rules out
dependencies, so `ZipArchive` is hand-rolled on top of `Compression` — the same
call the project made for EBML and ID3. Stored and deflate only; Zip64 is
refused rather than mis-parsed.

### Reading

`META-INF/container.xml` names the package document; the OPF's `<metadata>`
block is Dublin Core.

**Parsing is namespace-aware, never prefix-matching.** A `dc:` prefix is a local
nickname, and the developer's own copy of *The Secret Diary of Laura Palmer*
declares `<description>` in a *default* Dublin Core namespace instead. A prefix
matcher reads that file's summary as empty and reports no error.

| Wanted | Where it lives |
|---|---|
| Cover | manifest `properties="cover-image"` (EPUB 3), else `<meta name="cover">` naming a manifest id (EPUB 2 — what the real file uses) |
| Series | `belongs-to-collection` refinement (EPUB 3), else `calibre:series` — which is what actual libraries contain |
| ISBN | a `dc:identifier` with an `isbn` scheme, a `urn:isbn:` URI, or a bare 10/13-digit value |
| Year | the first four digits of `dc:date` |
| Subjects | every `dc:subject`, joined with `/` into one genre field |
| Contents | the EPUB 3 nav document, else the EPUB 2 NCX |

The table of contents is **read-only**. An EPUB's nav document is navigation
over content; rewriting it is editing the book, not tagging it.

### Writing

Two rules, both from the lossless round-trip invariant:

1. **The OPF is edited surgically.** Only the bytes inside `<metadata>` change,
   so the manifest, spine, guide and every namespace declaration survive.
   Regenerating the package document would be shorter and would throw the book
   away.
2. **Other entries are copied compressed.** Their original deflate streams are
   moved across untouched, so the rest of the book is byte-identical and a
   300 MB illustrated EPUB costs a copy rather than a recompression.

`mimetype` stays first and stored, as EPUB requires. Then the house discipline:
`TagBackupStore`, stage to a sibling temp, re-read to prove the metadata says
what we meant, atomic `replaceItemAt`.

A cover can be **replaced** but not **added** — a new manifest item would mean
rewriting the manifest and spine, which is bookbinding, not tagging.

## PDF

PDFKit's `documentAttributes`, both directions. Verified beforehand that a
metadata-only rewrite preserves annotations and outlines; there is a test that
fails if a future macOS stops doing so.

Refused rather than damaged: **encrypted or locked** files, and files carrying a
**digital signature**, which any rewrite invalidates. Same call the ID3 writer
makes on v2.2 tags.

The artwork well shows page one rendered, and says so — a PDF has nowhere to
store a cover, so `MediaTagReader.canWriteArtwork` returns false for it and the
inspector disables the controls rather than pretending.

## Providers

`MetadataProvider` is the protocol `ARCHITECTURE.md` always specified. The
wizard knows nothing about any service: it asks `MetadataProviders.serving(kind)`
and drives whatever comes back. Audible serves audiobooks, OpenLibrary serves
books, and the region picker only appears for providers that have storefronts.

### The ISBN OpenLibrary will not give you

An ISBN identifies an **edition**; an OpenLibrary search returns a **work**. The
Laura Palmer work lists sixteen ISBNs across six publishers. Picking one would
be inventing a fact, so an ISBN is offered only when the work has exactly one
unambiguous 13-digit identifier. Everything else about the book is still offered.

OpenLibrary also has no chapter data and never claims an ASIN.

## Testing

Fixtures are generated by `EPUBBuilder` in the test itself, never committed —
and shaped like the real file, default-namespaced `<description>` and all.

The load-bearing test is that archives written by `ZipArchive` open with
**`/usr/bin/unzip`**, not merely with our own reader. Under
`OMNITAG_REAL_MEDIA` the suite also reads *and rewrites* a copy of the
developer's real 3.4 MB EPUB, then checks entry count, chapter bytes and cover
survived and that `unzip -t` still passes. The copy is made first: a test never
writes to real media.

`OMNITAG_LIVE=1` adds two OpenLibrary checks, to catch the API changing its
answer.
